## Provider activation

| Provider | Required external configuration |
| --- | --- |
| Google | Use the existing web client or explicitly configure another approved web client in `NEXT_PUBLIC_GOOGLE_WEB_CLIENT_ID`. Authorize `https://learn.forrovivo.com` and, for this preview, `http://localhost` and `http://localhost:3002` in Google Cloud. The selected audience must also be accepted by Platform. Current console origin settings were not inspected. |
| Apple | Verify the default `com.forrovivo.learner.web` or override it with the registered Services ID as `NEXT_PUBLIC_APPLE_WEB_CLIENT_ID`, the exact registered HTTPS return URL as `NEXT_PUBLIC_APPLE_WEB_REDIRECT_URI`, and the same Services ID as the Worker's `APPLE_WEB_CLIENT_ID`. Associate the web service with the primary app in Apple Developer. A native bundle ID is not used as a substitute web registration. Full Apple acceptance needs the registered HTTPS environment. |

Reference setup: [Google Identity Services](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid), [Apple web configuration](https://developer.apple.com/help/account/capabilities/configure-sign-in-with-apple-for-the-web).

Only login, registration and reauthentication receive popup-compatible COOP and a referrer policy suitable for Google origin checks. Production uses `strict-origin-when-cross-origin`; development uses `no-referrer-when-downgrade`. Reset pages continue to use `no-referrer`, verified over production-mode HTTPS. No global TLS or session-validation checks were disabled.
