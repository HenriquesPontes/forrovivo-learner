# Login design and social sign-in — 21 October 2026

Login and registration now follow the supplied reference's centered panel, leafy title sign and separate social controls. The implementation uses ForroVivo's existing cream/green palette, Nunito typography, rounded outlines, pressed-button shadows and island illustration. It does not reuse the reference's brand, personal email or image assets.

`AuthShell` applies the new style to `/` and `/create-account`. Styles are scoped under `.auth-world`; Academy, account and recovery pages retain their existing layouts. The original session checks and redirects remain in place. Email forms retain their API payloads, autocomplete, validation limits, error states and account-bound session handling. Password visibility is optional and does not submit the form.

Both social options are visible. A missing provider configuration leaves its button disabled with an unavailable message; its SDK is not loaded. Configured Google sign-in uses Google's official rendered button. The existing Google web client ID from the Android/Platform configuration is now set in the ignored local environment. No Apple web Services ID was found or invented, so Apple remains unavailable until that ID is supplied and approved on the backend.

Social checks cover Google and Apple token submission, nonce/state handling, backend failure, Apple cancellation/state mismatch, SDK failure isolation, retry and Strict Mode nonce sharing. Overlapping mounts share one in-flight challenge so SDK and cookie nonces cannot diverge because of competing responses. No real provider account or email was used in these tests.

## Provider activation

| Provider | Required external configuration |
| --- | --- |
| Google | Use the existing web client or explicitly configure another approved web client in `NEXT_PUBLIC_GOOGLE_WEB_CLIENT_ID`. Authorize `https://learn.forrovivo.com` and, for this preview, `http://localhost` and `http://localhost:3002` in Google Cloud. The selected audience must also be accepted by Platform. Current console origin settings were not inspected. |
| Apple | Supply the registered Services ID as `NEXT_PUBLIC_APPLE_WEB_CLIENT_ID`, the exact registered HTTPS return URL as `NEXT_PUBLIC_APPLE_WEB_REDIRECT_URI`, and the same Services ID as the Worker's `APPLE_WEB_CLIENT_ID`. Associate the web service with the primary app in Apple Developer. A native bundle ID is not used as a substitute web registration. Full Apple acceptance needs the registered HTTPS environment. |

Reference setup: [Google Identity Services](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid), [Apple web configuration](https://developer.apple.com/help/account/capabilities/configure-sign-in-with-apple-for-the-web).

Only login, registration and reauthentication receive popup-compatible COOP and a referrer policy suitable for Google origin checks. Production uses `strict-origin-when-cross-origin`; development uses `no-referrer-when-downgrade`. Reset pages continue to use `no-referrer`, verified over production-mode HTTPS. No global TLS or session-validation checks were disabled.

## Verification and limits

- 46 regression/DOM tests pass across five files, including both providers and the new password control.
- Zero-warning lint, Webpack production build and TypeScript checks pass.
- Six HTTPS integration checks pass against actual local Platform routes/temporary SQLite, including OAuth page headers and reset privacy. The standalone fixture suite is recorded separately.
- Local preview runs at `http://localhost:3002`. No Vercel or Worker deployment was performed.

- Real Google/Apple sign-in is not certified by SDK or DOM tests. Provider console origin/return-URL approval, the missing Apple web ID and the Platform release gates in the main remediation report remain required.

The Nunito font and island artwork were copied unchanged from the existing public website. Nunito's OFL license and a SHA-256 provenance record are included beside the font. The uploaded reference remains outside the repository.

## English and Portuguese

Login and registration include an EN/PT switch, Portuguese (Portugal) labels, placeholders, password visibility labels, social controls, loading states and error messages. The `fv_learner_locale` preference cookie restores the selected language during server rendering; changing it preserves the typed form values. Google receives the matching button locale. The localized screen declares its language and restores the document language on exit. This browser preference does not rewrite a native account profile. The Academy and separate recovery pages are outside this translation pass.

Regression coverage verifies a language switch with filled credentials, Portuguese authentication errors, registration pending messages, and Portuguese server-rendered login/registration with the preference cookie. The previously removed provider note and website link remain absent.
